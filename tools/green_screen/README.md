# 绿幕批量抠图

浏览器里批量去绿幕背景，导出带透明通道的 PNG。纯前端、零依赖，图片不出本机。

## 用法

直接双击 `index.html` 打开即可（`file://` 下功能完整）。

想用本地服务器：

```bash
python3 -m http.server 8000 --directory tools/green_screen
# 打开 http://localhost:8000
```

流程：拖入图片 → 看预览调参数 → 「打包下载 ZIP」或「逐张下载」。

- 点缩略图放大，可切换看原图 / 抠图对比（Esc 关闭）
- 「吸管」→ 在预览图的幕布区域点一下，手动指定幕布色
- 大部分参数是全局的，一次调整对所有图生效；**裁切**和**点选**是逐图的

## 判定方式

两套算法，白底和绿幕走的不是同一条路：

| 方式 | 看什么 | 用在 |
| --- | --- | --- |
| 色度键 | 某个通道比另两个高出多少 | 绿幕、蓝幕 |
| 颜色距离 | 离幕布色差多少色阶（取三通道里差得最多的） | 白底、灰底、黑底、任意纯色底 |

默认「自动」：数一下四周边框里有多少像素是饱和的，够一批就是彩色幕布走色度键，
否则走颜色距离。卡片说明里会写明这张图实际走了哪条。

**白底必须走颜色距离。** 色度键量的是「通道间的差」，而白/灰/黑三个通道相等，
这个差恒为 0——幕布本身一点都扣不掉，反倒是偏色的前景（比如红色）差值大，
会被当成幕布扣掉并顺手去色。选了白色却扣掉一堆非白区域，就是撞在这上面。

## 参数

| 参数 | 作用 |
| --- | --- |
| 判定方式 | `自动` / `色度键` / `颜色距离`，见上。选定后无关的滑杆会自动收起 |
| 幕布颜色 | 默认自动识别（色度键取边框里超出量最大的一批求均值，颜色距离取边框中位数）。也可手动指定或吸管取色 |
| 色度键模式 | `均衡` 按相对纯度判定，背景明暗不均（有阴影）也能扣干净；`柔边` 按绝对差值判定，发丝、半透明边缘过渡更自然 |
| 阈值 | 仅色度键。调大保留更多，调小扣得更狠 |
| 颜色容差 | 仅颜色距离。与幕布色差多少色阶以内算背景。底色不匀、有压缩噪点就往大调 |
| 边缘过渡 | 容差/阈值往上的过渡宽度，越大边缘越柔 |
| 去绿边 | 仅色度键。削掉前景边缘吃到的绿色反光。全透明像素一律彻底去绿，避免引擎生成 mipmap 时从透明区吃出绿边 |
| 暗部保护 | 仅色度键。绿色超出量小于此值的像素一律当前景，防止近黑区域被误扣 |
| 色相容差 | 仅色度键。和幕布色相差太远的像素不参与抠除。调小可保住偏绿的前景 |
| 抠除范围 | 见下 |
| 收缩 | 蒙版向内收缩，啃掉一圈残留亮边 |
| 羽化 | 柔化蒙版边界 |
| 自动裁掉透明边 | 裁掉四周全透明区域，可留边距。做卡面素材时省事 |

蓝幕同样可用：算法会自动判断幕布色的主通道，绿幕走 G、蓝幕走 B。

## 抠除范围：保住画面里要留的白底

颜色判定是逐像素的，管不了「这块白在画面外面还是卡面里面」。卡面本身就是白底时，
按颜色扣会把卡里的白一起扣穿。用连通性把范围圈住：

| 范围 | 行为 |
| --- | --- |
| 全图 | 同色一律扣掉（老行为） |
| 只扣连到画面边缘的 | 从四周往里漫水，扣不到被前景围住的白 |
| 只扣点选的区域 | 只扣你点过的那几摞连通区域 |

多数情况「只扣连到画面边缘的」直接就对了，不用点。要留的白被前景完全围住时它最稳。
底色和画面边缘不接触（比如四周还有别的东西）才需要「只扣点选的」：按「点选背景」，
在预览图上点背景，可点多处，点过的位置会画个圈；「清除点选」清掉所有图的点。
一个点都没点时什么都不扣——不会默默把整张图扣了。

漫水只走「明显是幕布」的像素，边缘那圈半透明过渡标到就停，不再往外扩，
所以一圈只有 1px 宽的描边也挡得住，里面的白留得下来。

## 裁切

卡片上的「裁切」，或放大预览里的「裁切」：在图上拖出要保留的范围 →「应用裁切」
（Enter 也行）。「取消裁切」恢复整张，「退出」放弃这次拖拽，Esc 同「退出」。

裁切是逐图的，存的是归一化坐标，所以预览和全分辨率导出用的是同一个框。
顺序上先裁切再判定，被裁掉的部分不会再把自动取色带偏。裁切和「自动裁掉透明边」
可以叠着用：先按你的框裁，再削掉剩下的透明边。

「恢复默认」只重置全局参数，不会清掉各图的裁切框和点选。

## 已知限制

前景里如果有**和幕布同色相、且纯度接近**的颜色（比如纯绿幕上放一片饱和的深绿叶子），
仅凭颜色无法和背景区分，会被一起扣掉。这是色度键抠像的固有限制，不是 bug ——
影视拍摄里遇到绿色主体就是靠换蓝幕解决的。

可以这样绕开：

- 把**阈值**调高到 0.78 以上，或
- 切到**柔边**模式（阈值 0.5 左右），或
- 用**抠除范围**从空间上圈住（前景是绿的但和背景不连通时，这条最干脆）

前三种实测都能保住深绿前景，同时背景仍然扣干净。色相不同或纯度较低的绿
（橄榄绿、雾霾绿、青绿、黄绿、灰绿）在默认参数下就能保住，不用调。

颜色距离这套还有两条：

- 它只看「离得多近」，不看色相。前景里有和底色接近的浅色（白底上的浅灰）会被一起扣掉，
  调小**颜色容差**或改用**抠除范围**圈住。
- 前景边缘那圈半透明像素混了底色，白底上抠出来的边会偏亮。介意的话上**收缩** 1~2px。
  色度键的「去绿边」对这套不适用（白底没有可削的通道超出量，硬削只会把前景压暗），
  所以选颜色距离时那根滑杆是收起来的。

## 文件

| 文件 | 说明 |
| --- | --- |
| `index.html` | 页面结构 |
| `style.css` | 样式 |
| `chroma.js` | 抠像算法，纯函数不碰 DOM，可在 Node 里单独调用 |
| `zip.js` | 极简 ZIP 打包（store 模式，PNG 已压缩就不再 deflate） |
| `app.js` | 界面逻辑：文件读取、预览渲染、导出 |

`chroma.js` 同时支持浏览器 `<script>` 和 Node `require`，方便脱离界面验证算法：

```js
const { chromaKey } = require('./chroma.js');

// 绿幕
chromaKey({ data, width, height }, { threshold: 0.3, mode: 'soft' });

// 白底：只扣连到边缘的，并先裁掉四周
chromaKey({ data, width, height }, {
  keyMethod: 'distance',
  keyColor: [255, 255, 255],
  distTolerance: 40,
  regionMode: 'border',
  crop: { x: 0.1, y: 0.1, w: 0.8, h: 0.8 },   // 归一化到原图
});

// 只扣点选的连通区域；seeds 也是归一化坐标
chromaKey({ data, width, height }, { regionMode: 'seeds', seeds: [{ x: 0.02, y: 0.02 }] });
```

返回值除 `data/width/height` 外还带 `keyColor`、`method`（实际走的判定方式）、
`offset`（裁切/trim 削掉了左上多少）和 `source`（原图尺寸）——后两个用来把归一化坐标
换算回结果图里的像素位置。

## 性能

预览按 512px 边长缩放，拖滑杆实时响应；导出走全分辨率。
1296×1728 全分辨率单张约 40ms，1536×1536 约 80ms。
